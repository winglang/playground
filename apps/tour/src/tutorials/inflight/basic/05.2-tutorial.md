# Referencing preflight data from inflight code - Compiler

The main hurdle that the Wing compiler needs to overcome when allowing inflight code to reference preflight data is that inflight and preflight code run at different times and on different machines. 

So the compiler can't simply pass pointers to data structures in memory between them.

It also needs to take care of network topology to allow communication between the different services and give them the permissions they need to access each other.

The best way to understand what the compiler does is to look at the artifacts that it generates for us:

You can see the ones that the compiler generates for our example in the **AWS/Terraform** compilation target window.

First, you can see that the **cloud.Bucket** and **cloud.Function** resources are implemented with an **AWS S3** service and a **Lambda** service respectively. 

You can also see that the inflight code that runs when the function is invoked is stored in another S3 bucket (under the **Default** resource). The code itself is in the **"inflight1.js"** asset.

We can see some important things that the compiler has done for us if we look deeper:
1. **It generates least privilege IAM policies** - see how the IAM Policy under the cloud.Function grants the function with the minimal permissions that it needs in order to perform the "put" action on our bucket.
2. **It creates environment variables that allow the runtime code to access the right cloud service** - see the environment variables that are defined for the Lambda under the cloud.Function and how they contain the data that is needed by the function's code to create an AWS S3 client and access the correct bucket with it.
3. **It generates the network topology that allows the different services to communicate with one one another** - see the "vpc_config" of the Lambda which is empty in this case, but could contain definitions when needed.

Without the Wing compiler's assistance in referencing preflight data from inflight code, developers would have to manually generate all of these definitions and to maintain them as the code changes. 

Saving all this manual work is the main benefit of having both execution phases in the same language and under the same compiler. But there are other benefits as well.
