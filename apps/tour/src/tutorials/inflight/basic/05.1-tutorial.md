# Contract per phase - Explanation

Check out the code in the Editor. It uses two different `cloud.Bucket` methods to add files to our bucket. The first one, `addObject`, is called from preflight code in line 7. The second, `put`, is called from inflight code in line 12.

While both methods serve a similar purpose, to add a file to the bucket, their implementation is very different because conditions in the two execution phases are very different from each other. 

In the preflight execution phase, which runs at compile time, services do not exist yet. So it is only possible to configure their setup. In the inflight execution phase services are already up and running, so it is possible to interact with them. But it is not possible to change their configuration.

So in infight, we use the `put` method that simply uploads a file to the bucket when it is called.

In preflight, we use the `addObject` method. It updates the configuration file that is generated during compilation with definitions to upload the file to the bucket during deployment.

If we wanted to call the bucket's `put` method from preflight code, it would't make sense since the bucket doesn't exist yet. Similarly, it would not make sense to call the bucket's `addObject` method from inflight code since the bucket's configuration is already set up.

This is why: 

> 1. ***There are two different contracts (or interfaces) for the same object in Wing: One for preflight and another for inflight.***
> 2. ***The Wing IDE extension will show you the relevant contract for the phase you are in.***
> 3. ***The compiler will not let you call a preflight method from inflight code or vice versa.***
