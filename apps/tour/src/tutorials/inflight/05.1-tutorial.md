# Contract per phase - Explanation

In the last step we used the cloud.Bucket ***put*** function to upload a file to a bucket whenever our inflight code was invoked.

In previous steps we used the cloud.Bucket ***addObject*** function in the preflight phase to pre-populate a bucket with a file during deployment.

You can see code that does both in the Editor now, and play with it in the Simulator window.

While both functions serve a similar purpose, we often need to perform very different actions on objects in the two execution phases. This is because the preflight phase is used for setting up the infrastructure configuration of our application and the services it uses. The inflight phase is used for running the application and performing runtime actions on the services it uses.

Let's continue with the bucket as our example:

In preflight, we need to be able to create our bucket, pre-populate it with files that would be available in it when the app starts, define events to be called when actions are performed on it, etc.

But in inflight, we need to be able to read, modify and delete files as the state of the app evolves. These are not relevant for the preflight phase because our app is not running and no one can interact with it when it is being set up.

This is why in Wing, we have two different contracts (or interfaces) for the same object: One for preflight and another for inflight.

The Wing IDE extension will show you the relevant contract for the phase you are in.
