# Contract per phase - In practice

Let's experience working with the cloud.Bucket's different contracts by writing code that will print the name and content of a file whenever it is added to the bucket.

#### Preflight contract of the cloud.Bucket
First, we need to configure the bucket to let us know when a file is added to it. This is done in the preflight phase because it is configuration.

To do it, type ***"bucket."*** in line 11 and see the available autocomplete options. Can you see that they make sense for the setup phase of the app?

Now, find the ***onCreate*** function in the options and select it. It has one parameter - an inflight function to run whenever a file is created in the bucket. Give it the ***onCreateHandler*** inflight function that is defined in line 5.

#### Inflight contract of the cloud.Bucket
The ***onCreateHandler's*** code is not complete, we need to add code that prints the file's content to it.

Type ***"bucket."*** in line 7 and see the available autocomplete options. Can you see that they make sense for the runtime phase of the app, and that they are different than the options you saw in the preflight phase before?

Now, find the ***get*** function and use it to get the file's content. 

Then you can print it to the log, similar to how we print the file's name above it.

***Hint:*** there is a ***solve*** button in the upper right corner of the editor if you have difficulties.

#### Run the code

You can now click on the cloud.Bucket in the ***Simulator window***, upload files to it, and watch the resulting logs.

You can also switch to the AWS/Terraform compilation target tab to see how the event listener is implemented using an SNS topic. Make sure to see the IAM policies that are generated by the compiler to allow all of these actions to be performed.

Having different contracts for the two execution phases is not the only way the Wing compiler helps us use the different execution phases.
